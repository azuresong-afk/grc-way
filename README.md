# «Аттестация» (`grc`)

Рабочее место специалиста по защите информации для аттестации информационных систем по требованиям ФСТЭК России. Ведёт объект от описания до оценки мер: классификация, базовый набор мер и его адаптация, оценка реализации автоматически по результатам «Сканера» и вручную по документам, интервью и осмотрам.

Продукт входит в семейство «Сканер» → «Устранение» → «Аттестация» и позже встраивается в оболочку «Платформа». Сейчас он работает самостоятельно: свой вход по паролю, свои проекты, «Сканер» по API или из сохранённых ответов.

## Что умеет MVP (этап 1)

- **Проекты и объекты.** Заказчики, проекты (договоры), участники. Объекты ГИС, ИСПДн и КИИ: описание, сегменты, хосты вручную или из активов «Сканера».
- **Классификация.** Мастер по таблице приказа (сейчас №117 для ГИС). Таблицы хранятся как данные с версией. Черновик утверждает другой человек.
- **Набор мер.** Базовый набор по классу из профиля «Сканера». Адаптация: исключение с обоснованием, компенсирующие меры, дополнение. Каждая адаптация — новая версия с утверждением.
- **Оценка.** Импорт прогона «Сканера» создаёт снимок результатов. Из него получаются предложенные статусы мер с доказательствами по хостам. Ручные доказательства: файл, интервью, осмотр. Испытатель подтверждает статус меры.
- **Сводка и поиск.** Процент реализации (авто, вручную, всего), несоответствия, очередь ручной оценки. Ctrl+K находит объекты, хосты и меры.
- **Честность данных.** Всё, что не сверено методистом с официальным текстом, помечено «Требует сверки». Это касается таблиц классификации и сопоставления мер с проверками «Сканера».
- **Журнал аудита.** Каждое изменяющее действие записывается. Журнал только дописывается, правку и удаление запрещает триггер БД. Выгружается в CSV.

Модель угроз, реестр СЗИ, оценка критичности уязвимостей, комплект документов и передача несоответствий в «Устранение» запланированы на этапы 2–3 ([план](docs/roadmap.md#7-этапы-и-задачи)).

## Быстрый старт

Нужны Docker с Compose v2 и `make`.

```sh
cp .env.example .env
# заполнить POSTGRES_PASSWORD, GRC_SECRET_KEY и GRC_BOOTSTRAP_ADMIN_PASSWORD (см. комментарии в файле)
make demo
```

`make demo` собирает и поднимает стенд, затем создаёт демо-проект: объект «ГИС «Учёт»», класс К2, 10 хостов, два импортированных прогона «Сканера» из фикстур. В конце команда печатает имена демо-пользователей и пароль.

Откройте http://localhost:18082 и войдите как `demo-meth` (методист). Без демо-данных хватит `make up` и входа администратором из `.env`.

| адрес | что там |
|---|---|
| http://localhost:18082 | интерфейс |
| http://localhost:18082/api/health/ready | готовность: `{"status":"ok","db":"ok"}` |
| 127.0.0.1:18002 | API напрямую, только с этой машины |
| 127.0.0.1:15434 | PostgreSQL, только с этой машины |

## Роли

| роль | что делает |
|---|---|
| Администратор | пользователи и роли, справочники, журнал аудита. Объекты проектов не видит (разделение обязанностей) |
| Методист | проекты, объекты, классификация, адаптация набора мер, сверка справочников |
| Эксперт | импорт прогонов «Сканера», статусы мер, доказательства, подтверждение |
| Наблюдатель | только чтение |
| Утверждающий | добавочная роль: утверждает класс и адаптацию, кроме своих правок |

## Частые команды

```sh
make up        # собрать и запустить стенд
make demo      # то же + демо-данные (повторный запуск ничего не меняет)
make backup    # дамп БД и файлов доказательств в backup/
make logs      # журналы сервисов
make down      # остановить (данные в томах сохраняются)
make test      # тесты бэкенда и фронтенда без Docker
make lint      # ruff, tsc, eslint
```

## Разработка

```sh
# API (SQLite, режим разработки)
cd backend && python3.12 -m venv .venv && . .venv/bin/activate && pip install -e ".[dev]"
GRC_DEV_MODE=1 alembic upgrade head && GRC_DEV_MODE=1 python -m app.refs.loader
GRC_DEV_MODE=1 GRC_BOOTSTRAP_ADMIN_PASSWORD='длинный-пароль' python -m app.bootstrap
GRC_DEV_MODE=1 uvicorn app.main:create_app --factory --port 18002
pytest && ruff check . && ruff format --check .

# Интерфейс (Vite проксирует /api на :18002)
cd frontend && npm ci && npm run dev
npm run typecheck && npm run lint && npm test
```

| часть | стек |
|---|---|
| `backend/` | Python 3.12, FastAPI, SQLAlchemy 2, Alembic (миграции `0001_…`, тест-страж цепочки), PostgreSQL 16 |
| `frontend/` | React 18, TypeScript strict, Vite 5, стили и классы «Сканера» (`src/tokens.css`, `src/styles.css`) |
| `reference/` | справочники в YAML; загружаются в БД при каждом старте, правки из интерфейса не затираются |

CI (GitHub Actions) на каждый push: ruff и pytest, миграции вверх-вниз на PostgreSQL 16, typecheck, lint, тесты и сборка фронтенда, сборка образов.

Работа ведётся задачами плана: ветка и PR на задачу, к PR со стороны интерфейса прикладываются скриншоты в светлой и тёмной теме.
