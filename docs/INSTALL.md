# Установка и сопровождение «Аттестации»

Документ для администратора стенда: установка, настройка, подключение «Сканера», обновление, резервное копирование и восстановление. Все команды выполняются из корня репозитория на сервере.

## 1. Требования

- Linux x86_64 с Docker Engine 24+ и плагином Docker Compose v2 (`docker compose version`). Для коротких команд нужен `make`, без него команды из `Makefile` можно выполнять вручную.
- 2 ядра, 4 ГБ памяти, 10 ГБ диска под образы и данные. Файлы доказательств добавляют к этому свой объём.
- Сборка образов скачивает пакеты из PyPI и npm и базовые образы из Docker Hub. В закрытом контуре соберите образы снаружи и перенесите их (`docker save` / `docker load`) или настройте зеркала.
- Свободные порты: 18082 (интерфейс). Порты 18002 (API) и 15434 (PostgreSQL) публикуются только на `127.0.0.1`.

Сервисы стенда:

| сервис | образ | назначение | данные |
|---|---|---|---|
| `web` | nginx-unprivileged | интерфейс и прокси `/api/*` → `app`, строгий CSP | — |
| `app` | python:3.12-slim | API; при старте применяет миграции, создаёт первого администратора, загружает справочники | том `app-data` (`/data/evidence` — файлы доказательств) |
| `db` | postgres:16-alpine | база данных | том `db-data` |

## 2. Установка

```sh
git clone https://github.com/azuresong-afk/grc-way.git && cd grc-way
cp .env.example .env
```

Заполните в `.env` три обязательных значения:

```sh
POSTGRES_PASSWORD=...             # openssl rand -hex 24
GRC_SECRET_KEY=...                # openssl rand -hex 32
GRC_BOOTSTRAP_ADMIN_PASSWORD=...  # не короче 12 символов
```

Пароль БД подставляется в строку подключения, поэтому берите его из букв и цифр (`openssl rand -hex` подходит). Файл `.env` содержит секреты: `chmod 600 .env`, в репозиторий он не попадает.

Запуск:

```sh
make up            # то же, что docker compose up -d --build --wait
```

Проверка:

```sh
docker compose ps                                  # все три сервиса healthy
curl -s localhost:18082/api/health/ready           # {"status":"ok","db":"ok"}
docker compose logs app | grep -E "администратор|справочники"
# создан администратор «admin»
# справочники: профилей 5; мер добавлено 362, …
```

Откройте `http://<сервер>:18082` и войдите администратором (`GRC_BOOTSTRAP_ADMIN`, по умолчанию `admin`). Дальше:

1. «Пользователи и роли» → «Добавить пользователя»: заведите методиста, экспертов, утверждающего. Администратор рабочих операций не выполняет и объектов проектов не видит.
2. Методист создаёт заказчика и проект, указывает номер проекта в «Сканере» (engagement) и участников.

`GRC_BOOTSTRAP_ADMIN_PASSWORD` используется только при первом запуске на пустой БД. Позже его можно удалить из `.env`.

### Демо-данные

```sh
make demo          # docker compose exec app python -m app.demo
```

Создаёт четырёх демо-пользователей (`demo-meth`, `demo-exp`, `demo-boss`, `demo-viewer`) и проект «Аттестация ГИС «Учёт» (демо)». Пароль берётся из `GRC_DEMO_PASSWORD`, иначе генерируется и печатается. Повторный запуск ничего не меняет. На рабочем стенде демо не запускайте, а если запустили — заблокируйте демо-пользователей в «Пользователи и роли».

### HTTPS

Интерфейс слушает HTTP на `0.0.0.0:18082`. Для доступа по сети поставьте перед ним обратный прокси с TLS (nginx, корпоративный балансировщик) и ограничьте прямой доступ к 18082 межсетевым экраном. В журнал аудита попадает адрес, с которого запрос пришёл в `web`. За внешним прокси это адрес самого прокси, поэтому для разбора инцидентов храните и журнал прокси.

Для публикации под префиксом (в составе «Платформы») соберите интерфейс с `VITE_BASE=/grc/` и `VITE_API_BASE=/api/grc`.

## 3. Настройка

Все переменные с комментариями — в [`.env.example`](../.env.example). После правки `.env` выполните `make up`: изменённые сервисы пересоздаются.

| переменная | по умолчанию | смысл |
|---|---|---|
| `GRC_WEB_PORT`, `GRC_API_PORT`, `GRC_DB_PORT` | 18082, 18002, 15434 | порты на хосте |
| `POSTGRES_DB`, `POSTGRES_USER`, `POSTGRES_PASSWORD` | grc, grc, — | БД; пароль обязателен |
| `GRC_DATABASE_URL` | собирается из `POSTGRES_*` | задайте, только если БД внешняя |
| `GRC_SECRET_KEY` | — | ключ подписи токенов и шифрования секретов, ≥ 32 символов |
| `GRC_AUTH_MODE` | local | `platform` появится на этапе 3 |
| `GRC_DEV_MODE` | 0 | `1` открывает `/docs` API; в эксплуатации `0` |
| `GRC_BOOTSTRAP_ADMIN`, `GRC_BOOTSTRAP_ADMIN_PASSWORD` | admin, — | первый администратор |
| `GRC_TOKEN_TTL_MINUTES` | 480 | срок жизни сеанса |
| `GRC_LOGIN_MAX_FAILURES`, `GRC_LOGIN_LOCKOUT_SECONDS` | 5, 300 | пауза после неудачных входов |
| `GRC_PARTIAL_WEIGHT` | 0.5 | вес «Частично» в проценте реализации |
| `GRC_EVIDENCE_MAX_MB` | 50 | предел файла доказательства; выше 50 поправьте `client_max_body_size` в `frontend/nginx.conf` |
| `GRC_SCANNER_*` | fixture | подключение к «Сканеру», см. ниже |
| `GRC_DEMO_PASSWORD` | случайный | пароль демо-пользователей |

**Смена `GRC_SECRET_KEY`** завершает все сеансы и делает нечитаемыми сохранённые зашифрованные секреты. Храните ключ вместе с резервными копиями.

## 4. Подключение «Сканера»

По умолчанию `GRC_SCANNER_MODE=fixture`: «Аттестация» берёт ответы «Сканера» из сохранённых фикстур. Так работают демо и стенды без «Сканера». Для работы с настоящим «Сканером»:

1. В «Сканере» заведите сервисную учётную запись с ролью `auditor` (только чтение).
2. В `.env`:
   ```sh
   GRC_SCANNER_MODE=live
   GRC_SCANNER_URL=https://scanner.example/api     # без «/» в конце
   GRC_SCANNER_USERNAME=grc-reader
   GRC_SCANNER_PASSWORD=...
   # или GRC_SCANNER_TOKEN=... вместо имени и пароля
   ```
3. Если сертификат «Сканера» выпущен своим УЦ, положите корневой сертификат рядом с `docker-compose.yml` и подключите его файлом `docker-compose.override.yml`:
   ```yaml
   services:
     app:
       volumes:
         - ./scanner-ca.crt:/etc/grc/scanner-ca.crt:ro
   ```
   и задайте `GRC_SCANNER_CA_FILE=/etc/grc/scanner-ca.crt`.
4. `make up`, затем под администратором: «Справочники» → «Обновление из «Сканера»» → «Сравнить со «Сканером»». Если появилось сравнение профилей мер, подключение работает. Ошибка выводится на этом же экране, например: «Сканер» не ответил за 20 с.
5. В карточке проекта укажите «Проект в «Сканере»» (номер engagement). Из него придут активы для состава объекта и прогоны для импорта.

Если «Сканер» в той же сети Docker, адрес вида `http://scanner-app:8000`. Если на этом же сервере в другом compose-проекте, подключите `app` к его сети через `docker-compose.override.yml`.

## 5. Обновление

```sh
make backup                 # сначала резервная копия (раздел 6)
git pull
make up                     # пересборка образов; миграции применяются при старте app
docker compose logs app | grep -E "миграции|Running upgrade|ошибка"
curl -s localhost:18082/api/health/ready
```

Миграции применяются автоматически и только вперёд. Справочники из `reference/` догружаются при старте: новое добавляется, правки, сделанные в интерфейсе, не затираются.

**Откат.** Схема БД после миграций может не подойти старой версии. Поэтому откат — это возврат кода (`git checkout <прежний тег или коммит>`, `make up`) и восстановление копии, снятой перед обновлением (раздел 7).

## 6. Резервное копирование

Состояние стенда — это три вещи: БД, файлы доказательств и `.env`.

```sh
make backup
# backup/grc-20261104-212215.dump            — дамп БД (pg_dump, формат custom)
# backup/grc-20261104-212215-evidence.tgz    — файлы доказательств из тома app-data
```

Каталог задаётся переменной: `make backup BACKUP_DIR=/srv/backup/grc`. Без `make`:

```sh
docker compose exec -T db sh -c 'pg_dump -U "$POSTGRES_USER" -d "$POSTGRES_DB" -Fc' > grc.dump
docker compose exec -T app tar czf - -C /data evidence > grc-evidence.tgz
```

Копию можно снимать на работающем стенде: дамп согласован на момент начала. Файлы доказательств неизменяемы, имя файла — sha256 содержимого. Файл, добавленный во время копирования, может попасть в архив без записи в БД; это безвредно.

Рекомендации:

- Запускайте по расписанию (cron, systemd timer) и уносите копии с сервера.
- `.env` (особенно `GRC_SECRET_KEY`) храните отдельно от копий, в хранилище секретов.
- Периодически проверяйте восстановление на отдельном стенде (раздел 7).

## 7. Восстановление

### На новом сервере или после потери томов

```sh
# код той же версии, что при снятии копии; .env с тем же GRC_SECRET_KEY
docker compose up -d --wait db
docker compose exec -T db sh -c 'pg_restore -U "$POSTGRES_USER" -d "$POSTGRES_DB" --clean --if-exists --no-owner' < backup/grc-<дата>.dump
make up
docker compose exec -T app tar xzf - -C /data < backup/grc-<дата>-evidence.tgz
```

При старте `app` пишет «пользователи уже есть — администратор не создаётся». Входите прежними учётными записями.

### Поверх работающего стенда

Данные стенда заменяются данными копии.

```sh
docker compose stop app web
docker compose exec -T db sh -c 'pg_restore -U "$POSTGRES_USER" -d "$POSTGRES_DB" --clean --if-exists --no-owner' < backup/grc-<дата>.dump
docker compose start app
docker compose exec -T app tar xzf - -C /data < backup/grc-<дата>-evidence.tgz
make up
```

### Проверка после восстановления

- `curl -s localhost:18082/api/health/ready` → `{"status":"ok","db":"ok"}`.
- Вход прежним пользователем, сводка проекта показывает те же проценты.
- В карточке меры с файлом-доказательством «Скачать» отдаёт файл. Если архив доказательств не восстановлен, скачивание завершается ошибкой, а записи в БД остаются.
- «Журнал аудита» содержит записи до момента копии.

## 8. Перенос и удаление

**Перенос на другой сервер:** `make backup` на старом, перенос `backup/` и `.env`, установка по разделу 2 без `make up`, затем восстановление по разделу 7.

**Остановка:** `make down` — данные в томах сохраняются.

**Полное удаление вместе с данными:** `docker compose down -v --rmi local`. Необратимо: сначала `make backup`.

## 9. Неполадки

| признак | причина и что делать |
|---|---|
| `app` перезапускается, в журнале `ошибка запуска: не задан POSTGRES_PASSWORD` или `GRC_SECRET_KEY не задан или короче 32 символов` | заполните `.env` (раздел 2) |
| `ошибка: пользователей нет, задайте GRC_BOOTSTRAP_ADMIN_PASSWORD` | первый запуск на пустой БД без пароля администратора |
| `password authentication failed` после смены `POSTGRES_PASSWORD` | пароль БД задаётся только при создании тома `db-data`. Верните прежний или смените его в БД: `docker compose exec db psql -U grc -c "ALTER USER grc PASSWORD '…'"` |
| вход «Неверное имя или пароль» для верного пароля | после `GRC_LOGIN_MAX_FAILURES` неудач подряд вход по этому имени приостановлен на `GRC_LOGIN_LOCKOUT_SECONDS` секунд |
| все пользователи разом вышли из системы | сменился `GRC_SECRET_KEY` или истёк `GRC_TOKEN_TTL_MINUTES` |
| импорт прогона: «Адрес «Сканера» не задан», ошибка TLS или 401 | проверьте `GRC_SCANNER_*` (раздел 4) |
| загрузка файла: 413 | файл больше `client_max_body_size` в `frontend/nginx.conf` |
| журналы | `make logs` или `docker compose logs app --tail=200`; ротация 5 × 10 МБ на сервис |
