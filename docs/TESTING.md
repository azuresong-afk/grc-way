# Ручная проверка «Аттестации» на стенде

Пошаговая проверка MVP (этап 1) на чистом стенде с демо-данными. У каждого шага есть ожидаемый результат. Шаги идут по порядку: следующие опираются на данные предыдущих. Числа указаны для демо-данных и фикстур «Сканера» из репозитория. Если число не совпало, это повод разобраться.

Проверка закрывает критерии приёмки MVP из [ТЗ](brief.md): объект «ГИС, класс К2» с 10 хостами, автоматические статусы с доказательствами, организационные меры ждут ручной оценки, адаптация с обоснованием отражается в проценте, повторный импорт создаёт новый снимок, несверенное видно как «Требует сверки», обе темы, тесты зелёные. Занимает около 30 минут.

## 0. Подготовка

| # | действие | ожидаемый результат |
|---|---|---|
| 0.1 | `cp .env.example .env`, заполнить `POSTGRES_PASSWORD`, `GRC_SECRET_KEY`, `GRC_BOOTSTRAP_ADMIN_PASSWORD`; для удобства задать `GRC_DEMO_PASSWORD` (≥ 12 символов). `GRC_SCANNER_MODE=fixture` | — |
| 0.2 | Если стенд уже поднимался: `docker compose down -v` (удаляет данные!) | тома `grc_db-data`, `grc_app-data` удалены |
| 0.3 | `make demo` | в конце: «демо-данные: создан проект «Аттестация ГИС «Учёт» (демо)» и объект «ГИС «Учёт»» (К2, 10 хостов)», список из четырёх пользователей и пароль |
| 0.4 | `make demo` ещё раз | «проект … уже есть — ничего не изменено» |
| 0.5 | `docker compose ps`; `curl -s localhost:18082/api/health/ready` | `db`, `app`, `web` в состоянии healthy; `{"status":"ok","db":"ok"}` |
| 0.6 | `docker compose logs app \| grep -E "администратор\|справочники"` | «создан администратор «admin»»; «справочники: профилей 5; мер добавлено 362, …; таблиц классификации добавлено 3» |

Пользователи (пароль у всех демо-пользователей один):

| имя | роль |
|---|---|
| `admin` | администратор (пароль из `.env`) |
| `demo-meth` | методист |
| `demo-exp` | эксперт |
| `demo-boss` | наблюдатель + утверждающий |
| `demo-viewer` | наблюдатель |

Для смены пользователя: кнопка «Выйти» внизу боковой панели. Можно держать нескольких пользователей в разных окнах инкогнито.

## Что записать в отчёт о проверке

Номер коммита (`git rev-parse --short HEAD`), дату, браузер и номера шагов, где результат расходится с ожидаемым, со скриншотом. Мелкие расхождения во времени и датах ожидаемы: они зависят от момента запуска `make demo`.
