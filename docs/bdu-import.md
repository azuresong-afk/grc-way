# Импорт БДУ ФСТЭК России (задача 2.2)

«Аттестация» загружает два перечня из Банка данных угроз безопасности информации
(bdu.fstec.ru). Сеть к сайту ФСТЭК не нужна: файл скачивает пользователь и
загружает на экране «Справочники → БДУ ФСТЭК» (право `refs.manage`, администратор).

| перечень | файл на bdu.fstec.ru | что хранится |
|---|---|---|
| угрозы (УБИ) | `thrlist.xlsx` | `bdu_threats`: номер, наименование, описание, источник, объект воздействия, нарушение К/Ц/Д, даты включения и изменения |
| уязвимости | `vullist.xlsx` | `bdu_vulns`: описание, ПО, CVSS 2.0/3.x/4.0, уровень опасности, наличие эксплойта, эксплуатация в реальных атаках, статус, меры, CVE, CWE |

## Порядок загрузки

1. Файл кладётся в том (`GRC_BDU_DIR`, в Docker `/data/bdu`) под именем sha256.
2. Файл разбирается, данные сравниваются с загруженными: новые, изменённые
   (по полям «было → стало»), пропавшие из выгрузки, возвращённые. Ничего не меняется.
3. Предупреждения: выгрузка старше загруженной, тот же файл, в файле меньше 90 %
   действующих записей (вероятно, неполная), пропущенные строки, нет важных столбцов,
   расхождение оценки CVSS с вектором, не определена дата выгрузки. При
   предупреждениях применение требует явного подтверждения.
4. «Применить»: файл разбирается заново и сравнивается ещё раз; если данные
   изменились после сравнения — отказ. Записи не удаляются: пропавшие из выгрузки
   помечаются исключёнными (`withdrawn_at`), на них могут ссылаться модели угроз.
5. Новая загрузка того же перечня делает прежнюю неприменённую устаревшей.
   Всё пишется в журнал аудита (`bdu.import.diff`, `bdu.import.apply`, `bdu.import.rejected`).

Скорость: 100 тысяч уязвимостей (размер `vullist.xlsx`) — разбор около 25 с,
применение первой выгрузки около 20 с, повторной — секунды. Предел файла — `GRC_BDU_MAX_MB` (400 МБ).

## Версия выгрузки

Дата берётся в таком порядке: указана при загрузке → дата `дд.мм.гггг` в строках над
заголовком → для угроз наибольшая «Дата последнего изменения данных» → дата изменения
файла в свойствах документа (`docProps/core.xml`). Источник даты показывается рядом с ней.
У записи хранятся версия первой загрузки и версия последнего изменения.

## Формат файла

Столбцы ищутся по заголовку (без учёта регистра, «ё», лишних пробелов) в первых
15 строках, порядок не важен, лишние столбцы пропускаются. Обязательные:

- `thrlist.xlsx`: «Идентификатор УБИ» (`1`, `1.0` или `УБИ.001`), «Наименование УБИ»;
- `vullist.xlsx`: «Идентификатор» (`BDU:2024-04835`), «Наименование уязвимости».

Распознаваемые заголовки и синонимы — `THREAT_COLUMNS` и `VULN_COLUMNS` в
`backend/app/domain/bdu.py`. Строка без распознаваемого идентификатора или
наименования пропускается и попадает в предупреждение с номером строки.

## Поля для Методики оценки уровня критичности уязвимостей (ФСТЭК, 30.06.2025)

- **CVSS 3.x** (п. 13): вектор из столбца «CVSS 3.0»/«CVSS 3.1». Версия — из префикса
  вектора, иначе из «Уровня опасности» («базовая оценка CVSS 3.1 составляет 8,8»),
  иначе из заголовка столбца. Оценка — из «Уровня опасности»; если её нет, считается
  по вектору (формула CVSS v3.1, `backend/app/domain/cvss.py`, отметка «расчёт»).
  Нет 3.x — специалист выбирает версию сам при оценке (задача 2.8).
- **Наличие эксплойта**: `public` (в открытом доступе), `exists`, `unknown`
  (данные уточняются), `none`, `other`; исходный текст хранится.
- **Эксплуатация в реальных атаках**: столбец «Эксплуатация в реальных атаках»
  (как в карточке уязвимости на сайте), при его отсутствии — «Связь с инцидентами ИБ»:
  `yes`, `no`, `unknown`, `other`.
- Подсказка показателя E (таблица 1, строка 4): эксплуатируется → «Эксплуатируется в
  реальных атаках»; есть эксплойт → «Имеются сведения о наличии эксплойта»; иначе
  «Отсутствуют сведения». Окончательно E выбирает специалист.

**Требует пересчёта** (п. 16, 19): если при загрузке изменились вектор или оценка
CVSS 3.x, наличие эксплойта, сведения об эксплуатации или статус уязвимости, у
уязвимости ставится `criticality_changed_at` и сохраняется, что изменилось. Реестр
оценок критичности появится в задаче 2.8: оценка, сделанная раньше этой отметки,
получит статус «требует пересчёта».

## Что не проверено на настоящих файлах

Сайт bdu.fstec.ru недоступен из среды разработки, поэтому разбор проверен на
образцах (`backend/app/integrations/bdu/sample.py`) с раскладкой, описанной выше.
Чтобы сверить с настоящей выгрузкой, нужны свежие `thrlist.xlsx` и `vullist.xlsx`:
если заголовки отличаются, достаточно добавить синоним в `bdu.py`.
